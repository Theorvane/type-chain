# Agent Release Constraints

The repository is private under manual governance and `type-chain` is not released. Keep it private until implementation, public API documentation, consumer-tarball verification, npm release-readiness, and independent review are complete. Then make it public and restore/verify GitHub rulesets before accepting public contributions. Until then, manually require issue scope, exact PR HEAD, green CI, resolved threads, and independent review; do not direct-push or merge `dev`/`main`. Do not run `npm publish`, tag, create GitHub Releases, configure trusted publishing, or set secrets without explicit user authorization and completed release readiness. Prefer GitHub Actions OIDC trusted publishing, never persistent repo tokens. Release lane is `dev` → `main` only; verify an installed tarball consumer before publication and registry readback before reporting success.
